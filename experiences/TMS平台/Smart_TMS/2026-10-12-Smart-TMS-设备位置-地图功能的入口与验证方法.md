经过：需确认 smarttms.dspreadserv.net（Dspread Smart TMS）是否提供设备位置地图，以及"开了地理围栏的设备才上报位置"这一点。

结论（实测路径）：
1) 设备列表 /v1/smart/terminals：挂了位置上报的设备，serial 后面会多一个蓝色地图图钉（DOM：tr 内 .icon-map-marker-alt）。点它右侧弹出面板（class="terminals-double right"），显示 serial + "Last seen: 时间" + Google 地图（maps.googleapis.com zh-CN 瓦片），设备点用 /v1/static/pin/Pin_WithinZone.png。没有 pin 的设备不显示位置。
2) 设备详情：点 serial 链接进入 view?serialNo=xxx（直接输入该 URL 会被重定向回列表，必须从列表点进去）。详情页顶部 tab：General / Location / Device Logs / Remote View / Installation History。Location 页含 "Current Geofence Profile" + "Geofence Status"（In-Zone 配 icon-Geo-InZone 图标）+ 地图定位点；"Current Geofence Profile" 的值可能为空，UI 只回填状态。
3) General 页有 STORE LAT / STORE LNG 输入框 + SAVE，可手工写入设备经纬度。
4) 左侧 Geofence 菜单：围栏 profile 列表（Profile Name / Status Enable / Start-End Date / Roaming / Modified By），行尾 icon-edit 打开弹窗，规则形如"绑定 Serial + If device(s) are out of range 1000 meter(s) over 5 minute(s)"，围栏判定依赖设备上报位置。
5) 反证法：一页 20 台设备 0 个 pin，只有关联围栏的那台有 → 位置是围栏设备上报而非全量采集。

关键教训/坑：
- 该站 ego 浏览器（dsh-ego-browser）只实现了 click/goto/js/scroll/screenshot/snapshot/switchtab/text/url 等，**没有 type / fill / closetab**：输入框必须用 JS 原生 setter + dispatchEvent(new Event('input',{bubbles:true})) 再点放大镜图标（.el-icon-search）触发搜索。
- 直接 XHR 调接口（如 /mdm/geofence/getTerGeofenceInfo）会 401，token 由前端拦截器加，别指望裸调；直接读 DOM/截图更快。
- 读取 localStorage/cookie 会被 Guardian 拦截（泄露凭据风险），不要尝试。
- 页面里同时存在多个同名 el-dialog（display:none），必须按 getComputedStyle(...).display==='block' 过滤；弹窗的 Cancel/Save 是 span.button 而非 button 元素。
- 详情页 tab 与左侧菜单项文本相同（如 Location、Geofence），点击要用精确匹配 + offsetParent 可见性判断，或点 ul li 内的 div。
