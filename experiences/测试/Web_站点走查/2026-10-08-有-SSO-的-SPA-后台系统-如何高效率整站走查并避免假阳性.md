【场景】被测站是 Keycloak 登录 + Vue/Element-Plus 的 SPA 后台（设备管理 TMS），30+ 路由。

【关键教训】
1. 别用"goto+立刻读 DOM"判断页面为空。SPA 数据是异步拉的，读太早会得到一堆假"暂无数据"。必须 goto → 等 4~5 秒 → 再读；或者用同源 iframe 加载路由后再读 iframe 文档（每个 iframe 是新实例，不受组件复用影响）。
2. 逐路由整站扫描的最高效姿势：注入钩子（window.onerror + fetch/XHR 包装）后用 Vue3 的 document.querySelector('#app').__vue_app__.config.globalProperties.$router.push(path) 做 SPA 导航，钩子不会因页面刷新丢失；用 iframe 批量扫更适合"只看渲染结果"。
3. 找 i18n 缺陷：切到非默认语言后在页面 innerText 里 grep /[a-z][a-zA-Z]*\.[a-z][a-zA-Z]{3,}/，能直接捞出漏翻译的 key 名（本次捞到 home.activationTitle 等），比人眼快。
4. 静态分析证明安全结论要挑对 chunk：Vite 打包按路由懒加载，在 index-*.js 里 grep 'end_session' 可能是"那个模块不在这块"，不能据此下结论。真正可靠的证据是运行时抓到的真实 URL（auth 请求里有没有 state/code_challenge）。
5. 有 Guardian 之类安全策略时，"退出登录"这类不可逆点击会被拦；改为静态证据 + 标注"待确认"，不要硬试。
6. 该浏览器内核会间歇性地把页面导航到内部 data: URL（cursor-badge-check 之类），此时所有 DOM 读取都作废；拿到奇怪的空结果先 location.href 确认当前页面。

【可复用步骤】
登录（Keycloak 表单填 #username/#password → #kc-login）→ 用 $router.push 采集全部路由 → 每页 iframe/等待后读文本 → 页面内 fetch 探测接口鉴权（不带 Authorization 一律应被拒）→ curl 看响应头/HTTPS/版本 → 表单点 Save 空提交验校验（不产生脏数据）→ 静态包 grep 弃用告警与缺失 i18n key。
【底线】生产站只做只读测试：不开新增/删除/发布，改过的偏好（语言）测完还原。
