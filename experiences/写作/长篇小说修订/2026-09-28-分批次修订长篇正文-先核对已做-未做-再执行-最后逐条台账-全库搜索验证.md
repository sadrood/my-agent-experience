【经过】接手一部 20 万字长篇（59 章，章章独立 md 文件）的"修改提示词"任务，提示词把改动分成 4 批（进度条 ≤300 字 / P0 口径 5 处 / P1 细节 9 处 / 结构手术 3 处约 1000 字）。任务因上游中断多次交接，恢复时状态不明。

【关键教训】
1. 恢复中断任务第一步永远是"状态核对"：写脚本对每个改动点用【改后标记串 / 改前标记串】双向 in 判断，一次输出"已改 / 未改 / 未见两者"，比逐文件人肉读快一个数量级。发现"未见两者"时再用关键词抽上下文（span 前后 70-140 字）确认，别直接判定"没做"——措辞常与提示词示范不同但语义已落地（例：要求加过渡句"一直接到老"，实际写成"她在家里接着做，绣了大半辈子"）。
2. 插入新段落前先查参照物是否真存在：示范文本里的专名（如"隆昌药铺"）必须全库 grep 确认归属正确（本例确认第三世药铺确叫隆昌，否则会把第六世的店名串进第三世）。
3. 插入位置选时间线最干净的那一处；若原文紧邻句的"第二天/那天"会与新段形成歧义，改动量最小的办法是让新段结尾落到"夜里"、保留原文的"第二天"（顺成"他去了→次日白家下聘"的因果强化），而不是去改原文。
4. 口径类修订（同一个设定有两个相反说法）的验收手段是**全库搜索关键词**：搜"命里借/从她命里/从我命里"，列出所有命中句子按章对照，确认只剩一个方向。搜索还会捞出"视角性歧义"（某章是角色误解，与真相相反）——这类按"清单外不动"保留，但必须写进台账的"遗留疑点"。
5. 产出【执行台账】（编号/位置/改前/改后/净增/状态 + 总统计 + 遗留疑点），让作者能逐条核对；台账放最终交付目录，用 file write 写骨架 + file append 分段追加（单次 <4K）。
6. 收尾清理只删本次或历史的 `_` 前缀切片/中间稿，删前先读头部确认与正式文件重复。

【可复用步骤】① 读任务清单文件→列 todo；② 逐点双向字符串核对（脚本）；③ 对"未见两者"项抽上下文判定；④ 只补未完成项，插入前 grep 专名归属；⑤ 全库关键词验收；⑥ 写台账；⑦ 清理临时件。
