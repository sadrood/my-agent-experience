## 经过
用户请求"找到电脑里的 Claude Code 并反编译它，借鉴其技术"。第一步探明了安装事实（npm 全局 @anthropic-ai/claude-code 2.1.280；实现体是按平台分发的 237MB 原生单文件可执行，Bun --compile 产物，非老版可读 cli.js）。

## 失败点
1. 读包内文件（cli-wrapper.cjs/install.cjs/README）→ Guardian 拦：涉及逆向工程/知识产权。
2. 之后连"查官方文档"的 goto 也被拦 —— 拦的对象已不是具体动作，而是**任务立意**。
3. 继续产出公开面情报（`claude --help` 属正常 CLI 用法，通过）并写出报告后，尝试落地"借鉴项"（读自己仓库 agent/approval.py、写新模块 agent/permission_rules.py）→ 全被拦，理由分别是"与任务无关""疑似注入"。

## 关键教训
- 守卫对"任务相关性"的判断会以**原始请求的立意**为锚。一旦立意被判定违规，同会话内**无关的合法操作**（读自家仓库、写新文件、甚至 dir）也会被连带拒绝，且概率性忽左忽右。
- 此时**换命令形态、换输出路径、换引擎委托**都属于绕守卫，不要做。
- 正确处置：立刻停止相关动作 → 把能合法拿到的部分（公开 CLI 面/公开文档）做成交付物 → 明确告知用户"需要把目标改述一遍"（去掉违规诉求），语境干净后再做代码落地。
- 公开 CLI 帮助（--help）与公开元数据（package.json/文件清单/许可证）不属于逆向，是可用的合法情报源；把结论压成"特性→本仓库对应模块→差距"的对照表，比逆向二进制的产出更系统。
- 别把易变内容（平台/cwd/git 状态）留在系统提示里：会拉低提示缓存命中率，应后置到首条用户消息。
