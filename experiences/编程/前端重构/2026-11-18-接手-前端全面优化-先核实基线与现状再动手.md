经过：接手被 502 中断的前端优化任务，交接摘要称"已重写 daemon 文件待审查"。

失败点/教训：
1) 交接摘要描述的改动可能根本不存在——中断时没落盘或被 snapshot 回滚。动手前先 git status + 查文件是否真实存在，别去"审查修复"不存在的代码（本例 daemon 文件、tsconfig.daemon.json 全无，stash 也空）。
2) "前端差距很大"的直觉需读代码验证：实际发现 .btn 的 hover/active/disabled/transition/success/danger 变体、卡片 hover lift、统一 :focus-visible 环、入场动画、prefers-reduced-motion 降级都已具备；视觉模型只看一张静态截图报的"按钮无状态反馈"是误判。不要为凑"做了很多"而硬改已经扎实的代码。
3) 真正的硬伤只有一个：Tailwind v4 的 @theme 只注册了 1 个 token，:root 里那套完整设计 token（颜色/圆角/阴影/间距）没桥接，导致 bg-card/text-muted/rounded-md 等 utility 根本生成不出来，组件被迫手写 CSS 类。

可复用步骤：
- 改前必跑 build+test 建立可验证基线（本例 desktop: npm run build / npm test，39 个 vitest）。
- 大段 CSS/源码用 python 小批量读（<2KB），否则工具输出会被折叠；用 first(pat) 先定位行号再精确读。
- @theme 桥接：颜色用 var() 引用主题变量（随 light/dark 级联）；语义色若与 :root 同名必须用字面值，否则 var 自引用成循环、变量失效。
- 验证主题级联用 js getComputedStyle 读 computed 值，别依赖截图——captureScreenshot 在大页面/有持续动画时频繁超时。
- 工作区混着别的会话在制品时，只 git add 自己改的单个文件，禁止 add -A。
