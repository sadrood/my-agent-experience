【经过】novelflow（多用户写作平台，sqlite: /opt/novelflow/data/novelflow.db）上向用户汇报"你有哪些书"时，直接 select * from projects 全表列出，结果把账号 hhh(user_id=12) 的书《楠哥觉醒无限体力…》当成用户（admin, user_id=1）的书报了出来，用户当场指出"这不是我的书"。

【教训】
1. 平台类数据库几乎都有归属字段（projects.user_id / owner_id），汇报"你的 X"之前必须 where user_id=?；先查 users 表确认用户对应的 id，再过滤。
2. 同一个库文件可能有多个同名副本：/opt/novelflow/backend/data/novelflow.db 是空表（TABLES: []），真身在 /opt/novelflow/data/novelflow.db。查错文件会得到空结果并误判"没有数据"，要 glob 出所有候选逐个验。
3. ssh + 嵌套 heredoc 传 python 脚本在 Windows cmd → bash 链路上极易被引号/EOF 打断；可靠做法：本地写 .py → scp 到 /tmp → ssh 里 sudo python3 /tmp/x.py，用完 rm 清理。
4. 命令里出现 .env 路径会被审批护栏拦截（策略 never 时按拒绝处理）；依赖排查只 grep 代码文件，别去 cat 环境变量文件。

【可复用步骤】
- 查归属：select id,user_id,title from projects → join users 得到账号名，再按目标账号过滤。
- 统计进度用子查询：章节数 count(chapters.project_id)、字数 sum(length(content))，一次出表。
- 下线 docker 服务（可逆优先）：docker update --restart=no <name> && docker stop <name>；验证三件事——docker ps -a 状态 Exited、restart=no（重启机器不自启）、对应端口 ss -ltn 不再监听；同时确认其他服务仍 active。数据目录保留，彻底删除需另行确认。
